2 · الإعداد الدائم على GitHub (مرة واحدة فقط)

الكود يبقى في مستودعك الخاص، ونضيف مستودعاً عاماً للتنزيلات فقط لا يحتوي أي كود. منه يحصل العميل على رابط تنزيل دائم لا يتغير، ومنه يقرأ البرنامج تنبيه التحديثات. كل إصدار جديد يُنشر إليه تلقائياً.

أ – إنشاء مستودع التنزيلات العام

  1. ادخل GitHub بحساب asfantrading-create ← زر + أعلى الصفحة ← New repository.
  2. الاسم بالضبط: firetwin-releases · اختر Public · علّم Add a README file ← Create repository.
  3. افتح ملف README ← أيقونة القلم ✏️ ← احذف المحتوى والصق محتوى الملف docs/releases-repo/README.md (صفحة تنزيل جاهزة باللغتين) ← Commit changes.

ب – إنشاء مفتاح النشر (Token)

  1. GitHub ← صورتك أعلى اليمين ← Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token.
  2. الاسم: firetwin-publish · المدة: سنة (أو بلا انتهاء) · Repository access: Only select repositories ← اختر firetwin-releases.
  3. Permissions ← Repository permissions ← Contents: Read and write ← Generate token ← انسخ المفتاح (يظهر مرة واحدة).

ج – حفظ المفتاح في مستودع الكود

  1. افتح مستودع الكود FireFightingSystemBuilding ← Settings ← Secrets and variables ← Actions ← New repository secret.
  2. الاسم بالضبط: RELEASES_TOKEN · القيمة: المفتاح الذي نسخته ← Add secret.
انتهى الإعداد. لا تحتاج إلى تكراره. إذا انتهت صلاحية المفتاح يوماً ما، أنشئ مفتاحاً جديداً وحدّث قيمة RELEASES_TOKEN.

د – نشر إصدار جديد (في كل مرة)

  1. (اختياري) اكتب ملاحظات الإصدار بالعربي والإنجليزي في docs/update/latest.json (أو اطلب من Claude). تأكد أن رقم الإصدار في package.json هو الرقم الجديد.
  2. مستودع الكود ← Releases ← Draft a new release ← Choose a tag: اكتب v1.1.0 (نفس الرقم) ← Create new tag ← Target: الفرع الذي فيه آخر نسخة ← Publish release.
  3. تلقائياً خلال 4–5 دقائق: يُبنى البرنامج، ويُنشر في مستودع التنزيلات العام مع دليلي المستخدم، ويُحدَّث ملف التنبيه latest.json.
  4. تحقق: افتح github.com/asfantrading-create/firetwin-releases/releases وتأكد من ظهور الإصدار وملفاته.

3 · اختبار النسخة قبل البيع

  1. على جهاز ويندوز نظيف (أو جهاز صديق) شغّل ملف التثبيت واتبع القسم 4.
  2. تأكد أن البرنامج يفتح كنسخة تجريبية 14 يوماً وأن الشارة 🔑 تعرض الأيام.
  3. أصدر ترخيص اختبار لنفسك من المولّد (شهري، باقة مختلفة)، وفعّله، وتأكد أن الأجزاء غير المشمولة تظهر بقفل 🔒.
  4. افتح دليل المستخدم من زر ❓ للتأكد أنه مرفق.
  5. جرّب النسخة المحمولة على فلاشة.

4 · التثبيت عند العميل ورسالة SmartScreen

لأن البرنامج غير موقّع بشهادة مدفوعة، يظهر عند أول تشغيل لملف التثبيت:

ما يراه العميلما يفعله
نافذة زرقاء Windows protected your PCيضغط More info ثم Run anyway.
تحذير من المتصفح عند التنزيل (Chrome / Edge)يختار Keep / الاحتفاظ.
برنامج حماية يطلب تأكيداًيسمح بالملف (Allow).

بعدها: اختيار اللغة ← الموافقة على الاتفاقية ← مجلد التثبيت ← Install ← Finish. هذه الخطوات موجودة في دليل المستخدم (القسم 3) بالصور، فأرسل الدليل مع الرابط.

لاحقاً (اختياري): لإزالة رسالة SmartScreen نهائياً يمكن شراء شهادة توقيع (سنوية) أو استخدام خدمة Microsoft Trusted Signing الشهرية، ثم إعادة البناء. البرنامج لا يحتاجها ليعمل أو ليُباع.

  1. استلم الطلب: اسم العميل والجهة، الخطة (شهري / سنوي / تاريخ مخصص)، عدد الأجهزة، والباقة المطلوبة (كامل أو جزء).
  2. معرّف الجهاز (اختياري): إذا أردت ربط الترخيص بجهاز واحد، اطلب من العميل تثبيت البرنامج والضغط على 🔑 ثم نسخ Machine ID وإرساله لك.
  3. افتح المولّد: انقر نقراً مزدوجاً على license-generator.html ليفتح في Chrome أو Edge. في المرة الأولى حمّل private.jwk.json واضغط «حفظ في هذا المتصفح» (على جهازك الشخصي فقط).
  4. املأ البيانات: الاسم والجهة والبريد والمقاعد والخطة، والصق معرّف الجهاز إن وُجد.
  5. اختر الباقة:
    • البرنامج كاملاً: كل شيء.
    • باقات جاهزة: الرشاشات والمضخات / إنذار الحريق الذكي / المخاطر الخاصة / التوعية الأساسية.
    • باقة مخصصة: علّم بالضبط المنشآت والمشاهد التدريبية ووحدات المختبر الذكي والصفحات التي دفع العميل ثمنها.
  6. علّم ترخيص مشرف للمدرّس أو المدرّب فقط.
  7. اضغط توليد مفتاح الترخيص ← تنزيل ملف .lic ← (اختياري) طباعة ملخص الترخيص للعميل كـ PDF.
  8. أرسل للعميل: ملف .lic + رابط البرنامج + دليل المستخدم. التفعيل: 🔑 ← «تحميل ملف ترخيص .lic» ← تفعيل.
  9. يُحفظ كل ترخيص تلقائياً في سجل التراخيص أسفل الصفحة؛ صدّره CSV شهرياً واحتفظ بنسخة.

7 · حماية المفتاح الخاص

أهم قاعدة: الملف private.jwk.json هو «ختم» شركتك. من يملكه يستطيع إصدار تراخيص للبرنامج.
  • احتفظ بنسختين احتياطيتين: فلاشة في مكان آمن + خزنة كلمات مرور أو مجلد سحابي مشفّر.
  • لا ترسله لأي عميل أو موظف مبيعات، ولا ترفعه إلى GitHub (المستودع مهيأ لتجاهل مجلد keys/).
  • استخدم المولّد على جهازك فقط. إذا حفظت المفتاح في المتصفح على جهاز مشترك فامسح بيانات المتصفح.
  • إذا تسرّب المفتاح: يمكن توليد مفتاح جديد وإعادة بناء البرنامج، لكن كل التراخيص القديمة ستتوقف ويجب إعادة إصدارها للعملاء.

8 · تنبيه العملاء بالتحديثات (تلقائي)

كل نسخة من الإصدار 1.1.0 فما فوق تقرأ عند التشغيل (إذا كان الجهاز متصلاً بالإنترنت) الملف latest.json من مستودع التنزيلات العام، فإذا وجدت إصداراً أحدث يظهر للعميل شريط أخضر «يتوفر إصدار جديد» مع زري «ما الجديد» و«تنزيل».

  • عند نشر أي إصدار جديد (القسم 2-د) يُحدَّث الملف تلقائياً، فلا تحتاج لفعل شيء آخر.
  • ملاحظات التحديث التي يراها العميل تُكتب في docs/update/latest.json قبل النشر (notes.ar و notes.en).
  • لتحديث إلزامي (إصلاح مهم): اجعل "mandatory": true أو ارفع "minVersion" فلا يظهر زر «لاحقاً».
  • احتياطياً يقرأ البرنامج أيضاً https://asfanco.com/firetwin/latest.json إن رفعته إلى موقعك.
مهم: التنبيه يعمل فقط في النسخ 1.1.0 فما فوق — لذلك وزّع على العملاء هذه النسخة أو أحدث من البداية.

9 · التحديثات والدعم

  1. بعد أي تحديث للبرنامج انشر إصداراً جديداً (القسم 2-د) — يتحدّث رابط التنزيل الدائم وتنبيه العملاء تلقائياً.
  2. العميل يرى «يتوفر إصدار جديد»، ينزّل ويثبّت فوق القديم — يبقى الترخيص والنتائج كما هي.
  3. للدعم اطلب دائماً: معرّف الجهاز، رقم الإصدار (Help ← About)، وصورة المشكلة.

Seller guide – English summary

  1. One-time setup: create the public repository firetwin-releases (paste docs/releases-repo/README.md as its README), create a fine-grained token with Contents read/write on it, and save it as the secret RELEASES_TOKEN in the code repository.
  2. Publish a version (no certificate needed): Releases → Draft a new release → tag v1.1.0 (= package.json version) → Publish. The workflow builds and publishes to the public repository and updates latest.json.
  3. Permanent link: https://github.com/asfantrading-create/firetwin-releases/releases/latest/download/FireProtectionDigitalTwin-Setup.exe
  4. Test on a clean Windows PC: trial, activation with a test key, locked parts, the ❓ user manual.
  5. SmartScreen: customers click More info → Run anyway (browsers: Keep). A code-signing certificate is optional and can be added later.
  6. License a customer: open license-generator.html → private key → customer data → monthly / yearly / custom → optional Machine ID → package (Full, Sprinklers & pumps, Smart fire alarm, Special hazards, Basic awareness or Custom selection of facilities, training scenes, Smart Lab modules and pages) → Generate → download .lic → send with the download link and manual. Renew or upgrade with Reuse in the ledger.
  7. Update notice: automatic — every copy from 1.1.0 on reads latest.json from the public repository and shows “A new version is available”. Edit the notes in docs/update/latest.json before tagging; "mandatory": true for required updates.
  8. Protect private.jwk.json: two offline backups, never share or commit it.
