2 · بناء نسخة للبيع ونشرها (دون شهادة توقيع)

البرنامج جاهز للبيع دون شراء شهادة توقيع (Code-Signing Certificate). الفرق الوحيد أن ويندوز يعرض عند التثبيت رسالة SmartScreen الزرقاء، ويتجاوزها العميل بزرّين (القسم 4).

الطريقة أ – إصدار رسمي (Release) موصى بها

  1. افتح المستودع على GitHub ← Releases ← Draft a new release.
  2. في Choose a tag اكتب v1.1.0 واختر Create new tag. في Target اختر الفرع الذي فيه آخر نسخة (حالياً claude/quirky-dijkstra-ekvkkm، أو main بعد الدمج).
  3. العنوان: Fire Protection Digital Twin 1.1.0، ثم اضغط Publish release.
  4. يبدأ البناء تلقائياً (Actions). بعد 3–4 دقائق يُرفق ملف التثبيت والنسخة المحمولة بصفحة الإصدار تلقائياً.
  5. نزّل الملفين من صفحة الإصدار (قسم Assets).

الطريقة ب – من صفحة Actions مباشرة

  1. GitHub ← Actions ← آخر تشغيل بعلامة ✅.
  2. أسفل الصفحة في Artifacts نزّل FireProtectionDigitalTwin-Windows (ملف zip) وفكّ ضغطه.
رقم الإصدار: لكل تحديث جديد ارفع رقم الإصدار في package.json (مثلاً 1.2.0) وأنشئ Release جديداً بالوسم v1.2.0. يستطيع Claude فعل ذلك لك عند الطلب.

3 · اختبار النسخة قبل البيع

  1. على جهاز ويندوز نظيف (أو جهاز صديق) شغّل ملف التثبيت واتبع القسم 4.
  2. تأكد أن البرنامج يفتح كنسخة تجريبية 14 يوماً وأن الشارة 🔑 تعرض الأيام.
  3. أصدر ترخيص اختبار لنفسك من المولّد (شهري، باقة مختلفة)، وفعّله، وتأكد أن الأجزاء غير المشمولة تظهر بقفل 🔒.
  4. افتح دليل المستخدم من زر ❓ للتأكد أنه مرفق.
  5. جرّب النسخة المحمولة على فلاشة.

4 · التثبيت عند العميل ورسالة SmartScreen

لأن البرنامج غير موقّع بشهادة مدفوعة، يظهر عند أول تشغيل لملف التثبيت:

ما يراه العميلما يفعله
نافذة زرقاء Windows protected your PCيضغط More info ثم Run anyway.
تحذير من المتصفح عند التنزيل (Chrome / Edge)يختار Keep / الاحتفاظ.
برنامج حماية يطلب تأكيداًيسمح بالملف (Allow).

بعدها: اختيار اللغة ← الموافقة على الاتفاقية ← مجلد التثبيت ← Install ← Finish. هذه الخطوات موجودة في دليل المستخدم (القسم 3) بالصور، فأرسل الدليل مع الرابط.

لاحقاً (اختياري): لإزالة رسالة SmartScreen نهائياً يمكن شراء شهادة توقيع (سنوية) أو استخدام خدمة Microsoft Trusted Signing الشهرية، ثم إعادة البناء. البرنامج لا يحتاجها ليعمل أو ليُباع.

المستودع خاص (Private)، لذلك لا يستطيع العميل التنزيل من GitHub مباشرة. انقل الملف إلى مكان تشاركه:

موقع الشركةارفع الملفات إلى صفحة تنزيل (مثلاً asfanco.com/download) وأرسل الرابط.

حجم ملف التثبيت حوالي 75–80 ميجابايت، فهو أكبر من حد مرفقات البريد وواتساب. أرسل رابطاً دائماً.

6 · إصدار ترخيص لعميل (شهري / سنوي / باقة)

1طلب العميل
2معرّف الجهاز
3المولّد
4ملف .lic

6السجل
  1. استلم الطلب: اسم العميل والجهة، الخطة (شهري / سنوي / تاريخ مخصص)، عدد الأجهزة، والباقة المطلوبة (كامل أو جزء).
  2. معرّف الجهاز (اختياري): إذا أردت ربط الترخيص بجهاز واحد، اطلب من العميل تثبيت البرنامج والضغط على 🔑 ثم نسخ Machine ID وإرساله لك.
  3. افتح المولّد: انقر نقراً مزدوجاً على license-generator.html ليفتح في Chrome أو Edge. في المرة الأولى حمّل private.jwk.json واضغط «حفظ في هذا المتصفح» (على جهازك الشخصي فقط).
  4. املأ البيانات: الاسم والجهة والبريد والمقاعد والخطة، والصق معرّف الجهاز إن وُجد.
  5. اختر الباقة:
    • البرنامج كاملاً: كل شيء.
    • باقات جاهزة: الرشاشات والمضخات / إنذار الحريق الذكي / المخاطر الخاصة / التوعية الأساسية.
    • باقة مخصصة: علّم بالضبط المنشآت والمشاهد التدريبية ووحدات المختبر الذكي والصفحات التي دفع العميل ثمنها.
  6. علّم ترخيص مشرف للمدرّس أو المدرّب فقط.
  7. اضغط توليد مفتاح الترخيص ← تنزيل ملف .lic ← (اختياري) طباعة ملخص الترخيص للعميل كـ PDF.
  8. أرسل للعميل: ملف .lic + رابط البرنامج + دليل المستخدم. التفعيل: 🔑 ← «تحميل ملف ترخيص .lic» ← تفعيل.
  9. يُحفظ كل ترخيص تلقائياً في سجل التراخيص أسفل الصفحة؛ صدّره CSV شهرياً واحتفظ بنسخة.

7 · حماية المفتاح الخاص

أهم قاعدة: الملف private.jwk.json هو «ختم» شركتك. من يملكه يستطيع إصدار تراخيص للبرنامج.
  • احتفظ بنسختين احتياطيتين: فلاشة في مكان آمن + خزنة كلمات مرور أو مجلد سحابي مشفّر.
  • لا ترسله لأي عميل أو موظف مبيعات، ولا ترفعه إلى GitHub (المستودع مهيأ لتجاهل مجلد keys/).
  • استخدم المولّد على جهازك فقط. إذا حفظت المفتاح في المتصفح على جهاز مشترك فامسح بيانات المتصفح.
  • إذا تسرّب المفتاح: يمكن توليد مفتاح جديد وإعادة بناء البرنامج، لكن كل التراخيص القديمة ستتوقف ويجب إعادة إصدارها للعملاء.

8 · التحديثات والدعم

  1. بعد أي تحديث للبرنامج أنشئ Release جديداً (القسم 2) وارفع الملف الجديد مكان القديم في رابط التنزيل.
  2. أبلغ العملاء: «نزّلوا النسخة الجديدة وشغّلوا ملف التثبيت» — يبقى الترخيص والنتائج كما هي.
  3. للدعم اطلب دائماً: معرّف الجهاز، رقم الإصدار (Help ← About)، وصورة المشكلة.

Seller guide – English summary

  1. Build a release (no certificate needed): GitHub → Releases → Draft a new release → tag v1.1.0 on the latest branch → Publish. The workflow attaches Setup and Portable .exe files in ~3–4 minutes (or download them from Actions → Artifacts).
  2. Test on a clean Windows PC: trial, activation with a test key, locked parts, the ❓ user manual.
  3. SmartScreen: customers click More info → Run anyway (browsers: Keep). A code-signing certificate is optional and can be added later.
  4. Distribute through a Google Drive / OneDrive / website link or USB — the file (~80 MB) is too large for e-mail/WhatsApp attachments; the GitHub repository is private.
  5. License a customer: open license-generator.html → private key → customer data → monthly / yearly / custom → optional Machine ID → package (Full, Sprinklers & pumps, Smart fire alarm, Special hazards, Basic awareness or Custom selection of facilities, training scenes, Smart Lab modules and pages) → Generate → download .lic → send with the download link and manual. Renew or upgrade with Reuse in the ledger.
  6. Protect private.jwk.json: two offline backups, never share or commit it.
